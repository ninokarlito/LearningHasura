Kubernetes adalah sebuah platform yang digunakan untuk mengelola, menjadwalkan, dan mengatur beban kerja berbasis container dalam skala besar. Namun, definisi Kubernetes sering kali menjadi perdebatan karena ada banyak perspektif mengenai apakah Kubernetes adalah **platform, infrastruktur, atau aplikasi**. Daripada memperdebatkan definisi tersebut, lebih baik kita fokus pada **masalah yang diselesaikan oleh Kubernetes** dan bagaimana fitur-fitur yang dimilikinya membantu mencapai **kondisi Kubernetes produksi**—di mana workload atau aplikasi dapat berjalan dengan stabil dan siap menangani trafik pengguna secara nyata.

## Kubernetes dalam Ekosistem Open Source

Ketika kita berbicara tentang **Kubernetes**, kita sebenarnya berbicara tentang sebuah proyek open-source yang sangat luas. Jika kita melihat repositori di **GitHub**, kita akan menemukan:

- **Organisasi GitHub `kubernetes`**, yang memiliki sekitar **69 repositori** (pada saat tulisan ini dibuat).
- **Organisasi `kubernetes-sigs`**, yang memiliki lebih dari **107 proyek**.
- **Ekosistem CNCF (Cloud Native Computing Foundation)**, yang memiliki ratusan proyek terkait Kubernetes.

Namun, dalam konteks pembahasan ini, kita akan fokus pada **proyek inti Kubernetes**, yaitu yang terdapat dalam repositori [`kubernetes/kubernetes`](https://github.com/kubernetes/kubernetes) di GitHub.

## Apa yang Ada di Repositori `kubernetes/kubernetes`?

Repositori ini adalah inti dari Kubernetes dan berisi **komponen utama** yang biasanya ada di setiap kluster Kubernetes. Jika kita menjalankan kluster Kubernetes dengan komponen-komponen ini, maka kita mendapatkan fitur-fitur berikut:

1. **Menjadwalkan beban kerja pada banyak host**  
   Kubernetes dapat mendistribusikan container ke berbagai server (node) dan mengelolanya secara otomatis.

2. **Menyediakan API yang deklaratif dan dapat diperluas**  
   Kubernetes memiliki API yang memungkinkan pengguna untuk mendeklarasikan bagaimana aplikasi harus berjalan, dan sistem akan secara otomatis memastikan konfigurasi tersebut diterapkan.

3. **Menyediakan CLI (`kubectl`) untuk berinteraksi dengan API Server**  
   Dengan menggunakan `kubectl`, pengguna dapat menjalankan perintah untuk mengelola kluster, melihat status aplikasi, serta mengelola deployment.

4. **Rekonsiliasi antara keadaan saat ini dan keadaan yang diinginkan**  
   Kubernetes secara otomatis akan menyesuaikan keadaan sistem dengan konfigurasi yang telah dideklarasikan oleh pengguna.

5. **Menyediakan abstraksi layanan (Service) untuk membantu routing trafik**  
   Kubernetes memiliki mekanisme layanan (Service) yang memungkinkan aplikasi untuk tetap dapat diakses meskipun pod atau container di belakangnya berubah.

6. **Menyediakan antarmuka untuk integrasi jaringan, penyimpanan, dan ekstensi lainnya**  
   Kubernetes mendukung berbagai plugin yang memungkinkan integrasi dengan sistem penyimpanan (Storage), jaringan (Networking), serta berbagai fitur lainnya.

## Kubernetes: Sebuah **Container Orchestrator**

Berdasarkan fitur-fiturnya, Kubernetes mendefinisikan dirinya sebagai **"production-grade container orchestrator"**, atau **orchestrator container untuk lingkungan produksi**. Dalam istilah yang lebih sederhana, Kubernetes adalah sistem yang memungkinkan kita menjalankan dan mengelola container dalam skala besar di berbagai host.

## Kesimpulan

**esensi utama Kubernetes adalah mengelola workload berbasis container secara otomatis**. Dengan memahami fungsi-fungsi dasar ini, bisa mulai menjelajahi bagaimana Kubernetes dapat membantu dalam proses deployment aplikasi, otomatisasi skala besar, serta pengelolaan aplikasi dalam produksi.

# **Komponen Inti Kubernetes**  

## **Pendahuluan**  
Komponen inti Kubernetes terdapat dalam **repository `kubernetes/kubernetes`** di GitHub.  
- Setiap pengguna bisa mengakses komponen ini dengan **cara berbeda**:  
  - **Menggunakan layanan terkelola** seperti **Google Kubernetes Engine (GKE)** → Komponen sudah tersedia di dalam node.  
  - **Mendownload dan menginstal sendiri** dari repository Kubernetes.  
  - **Mendapatkan versi resmi** dari vendor tertentu.  

## **Mendownload dan Mengekstrak Komponen Kubernetes**  
Siapa pun dapat mengunduh rilis Kubernetes dari repository utama. Setelah diunduh, kita bisa menggunakan **script berikut** untuk mendapatkan komponen klien dan server:  

```sh
$ ./cluster/get-kube-binaries.sh
```

📌 Contoh output:  
```
Kubernetes release: v1.18.6
Server: linux/amd64 (to override, set KUBERNETES_SERVER_ARCH)
Client: linux/amd64 (autodetected)
Will download kubernetes-server-linux-amd64.tar.gz from https://dl.k8s.io/v1.18.6
Will download and extract kubernetes-client-linux-amd64.tar.gz
Is this ok? [Y]/n
```

- File utama yang diunduh:  
  ```
  server/kubernetes-server-${ARCH}.tar.gz
  ```

## **Komponen Utama Kubernetes**  
Setelah mengekstrak **kubernetes-server-${ARCH}.tar.gz**, kita akan menemukan beberapa komponen kunci dalam kluster Kubernetes:

### **1. API Server (`kube-apiserver`)**  
📌 **Fungsi Utama**  
- Titik utama interaksi antara **pengguna dan komponen Kubernetes**.  
- API Server digunakan untuk **mendapatkan, menambahkan, menghapus, dan memperbarui objek** dalam kluster.  
- Menyimpan **status kluster** dalam **etcd** (database key-value).  

🔹 **Peran dalam Kluster**  
- Semua permintaan dari **kubectl, dashboard, atau sistem lain** diproses oleh API Server.  
- Menyediakan **API RESTful** untuk mengelola sumber daya Kubernetes.  

---

### **2. Kubelet (`kubelet`)**  
📌 **Fungsi Utama**  
- Agen yang berjalan di **setiap node Kubernetes** untuk **berkomunikasi dengan API Server**.  
- Memastikan bahwa **container dijalankan sesuai instruksi API Server**.  
- Menggunakan **container runtime** seperti Docker untuk menjalankan container.  

🔹 **Peran dalam Kluster**  
- Memantau kesehatan container dan melakukan restart jika gagal.  
- Mengelola **lifecycle Pod** yang berjalan di dalam node.  

---

### **3. Controller Manager (`kube-controller-manager`)**  
📌 **Fungsi Utama**  
- Mengelola **controller dalam Kubernetes** untuk memastikan kluster berjalan sesuai dengan **desired state**.  
- Contoh perannya:  
  - **Deployment Controller** → Memastikan jumlah Pod sesuai dengan yang dideklarasikan.  
  - **Node Controller** → Mengecek apakah ada node yang tidak merespons.  
  - **Service Controller** → Mengelola service dan endpoint untuk komunikasi antar aplikasi.  

🔹 **Peran dalam Kluster**  
- Jika kita meminta **3 replika Pod**, **Controller Manager akan memastikan 3 Pod berjalan**.  
- Jika ada **Pod atau Node yang mati**, maka akan dibuat ulang.  

---

### **4. Scheduler (`kube-scheduler`)**  
📌 **Fungsi Utama**  
- Bertugas memilih **node terbaik** untuk menjalankan **Pod baru** berdasarkan **filtering dan scoring**.  

🔹 **Peran dalam Kluster**  
- Scheduler mempertimbangkan faktor seperti:  
  - **Kapasitas CPU dan RAM**.  
  - **Affinity dan Anti-Affinity Rules** untuk mengatur distribusi Pod.  
  - **Taints dan Tolerations** untuk menentukan node yang boleh menjalankan Pod tertentu.  

---

### **5. Kube Proxy (`kube-proxy`)**  
📌 **Fungsi Utama**  
- Menyediakan layanan **jaringan dalam Kubernetes**.  
- Mengatur **routing traffic** antara service dan Pod menggunakan **iptables atau ipvs**.  

🔹 **Peran dalam Kluster**  
- Mengatur **load balancing internal** antar Pod.  
- Memastikan Pod di **node berbeda tetap bisa berkomunikasi** melalui Virtual IP.  

---

# **Kesimpulan**  
Kelima komponen di atas adalah **inti dari sistem Kubernetes**. Berikut adalah **ringkasan fungsi tiap komponen** dalam kluster Kubernetes:  

| **Komponen** | **Fungsi Utama** |
|-------------|----------------|
| **API Server** | Mengelola permintaan dari pengguna dan komponen lain. |
| **Kubelet** | Mengontrol container di dalam setiap node. |
| **Controller Manager** | Menjalankan berbagai controller untuk memastikan keadaan kluster sesuai yang diinginkan. |
| **Scheduler** | Menentukan node terbaik untuk menjalankan Pod baru. |
| **Kube Proxy** | Mengatur jaringan dan komunikasi antar Pod. |

Selain itu, arsitektur Kubernetes memiliki **banyak variasi**. Misalnya:  
- **API Server, Scheduler, dan Controller Manager dapat berjalan sebagai container** dalam kluster.  
- **Control Plane bisa berjalan di dalam container runtime** bersama kubelet dan kube-proxy.
